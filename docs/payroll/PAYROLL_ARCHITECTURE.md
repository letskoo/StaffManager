# Staff Manager 급여 계산 코드 구조

> 이 문서는 Staff Manager 급여 계산 코드의 구조와
> 계산식별 분리 상태를 관리하는 문서다.
>
> PAYROLL_POLICY.md가 "어떻게 계산할 것인가"를 정의한다면,
> 이 문서는 "그 계산 코드가 어디에 있는가"를 관리한다.

---

# 1. 기본 원칙

급여 계산은 Staff Manager의 핵심 기능이다.

계산식 수정 시 다른 급여 계산에 영향을 주지 않도록
가능한 한 계산 항목별로 코드를 분리한다.

다만 기존 기능 전체를 한 번에 리팩터링하지 않는다.

급여 계산을 실제로 수정하거나 검증하는 시점에
해당 계산부터 하나씩 별도 파일로 분리한다.

즉,

정책 확정
→ 기존 계산 위치 확인
→ 계산식별 파일 분리
→ 계산식 수정
→ 테스트
→ 검증 완료

순서로 진행한다.

---

# 2. 현재 주요 급여 서비스

## payCommon.js

공통 급여 계산 유틸리티.

현재 포함 기능 예:

- 근무 예정시간 계산
- 시간 겹침 계산
- 야간시간 계산
- 휴일 근무시간 분리
- 시간급 환산

주의:

현재 월급제 시간급 환산에
`월급 ÷ 209` 고정 계산이 존재한다.

일반 월급제 지각·조기퇴근·휴게초과 계산에서는
이 고정 계산을 제거할 예정이다.

---

## hourlyPayService.js

현재 `calculatePayDetail()`을 중심으로
여러 급여 계산이 함께 존재한다.

현재 포함된 주요 계산:

- 기본 근무
- 지각
- 조기출근
- 조기퇴근
- 휴게시간
- 휴게시간 초과
- 연장근무
- 야간근무
- 휴일근무

장기적으로 계산 항목별 분리를 진행한다.

---

## monthlyPayService.js

월급제 월 급여 집계 및 월 단위 계산을 담당한다.

현재 포함된 주요 계산:

- 월 기본급
- 결근 차감
- 지각 차감 집계
- 조기퇴근 차감 집계
- 휴게초과 차감 집계
- 주휴 관련 계산
- 월 급여 최종 집계
- 급여명세서용 계산

이 파일 역시 필요한 계산부터 단계적으로 분리한다.

# 4. 현재 작업 대상

현재 작업에서는 다음 세 가지 월급제 계산만 다룬다.

1. 지각
2. 조기퇴근
3. 휴게시간 초과

이번 작업에서는 다음 항목을 수정하지 않는다.

- 결근
- 조기출근
- 연장근무
- 야간근무
- 휴일근무
- 주휴수당

기존 기능에 불필요한 영향을 주지 않기 위해
현재 작업 범위를 엄격하게 제한한다.

# 5. 월급제 계산기 폴더

현재 생성된 폴더:

src/services/pay/calculators/monthly/

현재 계획:

src/services/pay/calculators/monthly/
├─ lateDeduction.js
├─ earlyLeaveDeduction.js
└─ breakDeduction.js

위 파일은 실제 해당 계산을 수정할 때 하나씩 생성한다.

아직 수정하지 않는 급여 계산 파일은
미리 생성하지 않는다.

---

# 6. 분리 작업 원칙

계산식별 파일은 하나의 급여 정책을
가능한 한 독립적으로 계산하도록 만든다.

예:

lateDeduction.js

입력:
- 월급
- 계산 대상 날짜
- 정상 출근시간
- 실제 출근시간
- 승인 상태
- 필요한 직원 근무정책

출력:
- 지각시간
- 지각 차감금액

다른 계산기에서 지각 계산식을
중복 구현하지 않는다.

---

# 7. 공통 계산과 정책 계산의 구분

여러 급여 정책에서 공통으로 사용하는 기능은
payCommon.js 또는 별도의 공통 계산 모듈에 둔다.

예:

- 해당 월의 역일수
- 날짜 계산
- 예정 근무시간
- 정상 급여 인정시간
- 공통 시간 변환

반면 정책에 따라 결과가 달라지는 계산은
각 계산기 파일에서 담당한다.

예:

- 지각 차감
- 조기퇴근 차감
- 휴게초과 차감
- 결근 차감
- 연장수당
- 야간수당

---

# 8. 리팩터링 금지 원칙

급여 계산 구조를 정리한다는 이유로
정상 작동 중인 모든 급여 코드를 한 번에 이동하지 않는다.

다음 조건 중 하나에 해당할 때만 분리한다.

- 해당 계산식을 수정해야 할 때
- 해당 계산을 테스트해야 할 때
- 다른 계산과 충돌이 확인됐을 때
- 중복 계산식이 발견됐을 때

분리 후에는 반드시 기존 결과와 비교 테스트한다.
